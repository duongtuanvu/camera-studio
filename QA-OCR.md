# OCR regression v0.3.1
- Reproduced the issue using a local crop of the user-provided screenshot, not a clean-text example. Screenshot not committed.
- Native Tesseract 5.5.0 with Vietnamese + English, after resizing the screenshot crop from 268 x 476 to 804 x 1428 and applying the same grayscale formula used by the new adapter, PSM 6 recognized INDONESIA, GN-4422GB, 393L, 500kWh, 90W, 1,46 and TCVN7828:2016. Selected fields are not a complete transcription metric; accents and other characters remain incorrect. The browser WASM build and camera device are different test environments.
- 16 new Node tests passed locally for preprocessing, candidate selection and confirmation. Coverage of document-ocr.mjs: lines 100%, functions 100%, branches 90.32%.
- New independent synthetic energy label PNG in tests/fixtures/energy-label.b64 uses green background and cream text, with values 250L, 80W, 400kWh/năm; native Tesseract read all three. Added WASM regression in scripts/ocr-smoke.mjs. WASM gate and mobile QA not run locally due npm registry DNS failure.
- Auto now prefers Tesseract (two layout passes for documents); PaddleOCR remains an explicit experimental choice and document-init fallback. No new packages or cloud OCR endpoint.
- The candidate selection heuristic is not a completeness or accuracy guarantee. All OCR output, including high confidence output, now requires editable manual review and explicit confirmation before copy/save. Editing resets confirmation. Numeric review enforces a single number. User confirmation is not automated accuracy validation.
